# 📱 مصدر تطبيق Holy (أندرويد)

هذا المجلد يحمل مصدر تطبيق Holy وأداة بنائه. المصدر الأصلي لم يكن محفوظاً، فاسترجعناه من التطبيق المدمج في اللوحة (النسخة 1.9، الرمز 10)، وأداة البناء تعيد بناءه من هنا.

| المسار | ما فيه |
|---|---|
| `smali/` | شيفرة التطبيق كما فكّها baksmali 2.5.2 من `classes.dex` (التجميع ثم الفك من جديد يعطي النص نفسه حرفاً بحرف) |
| `java/` | الأجزاء الجديدة المكتوبة بجافا 8 (إن وجدت) |
| `base/` | `AndroidManifest.xml` و`resources.arsc` و`res/` كما هي داخل التطبيق (بصيغتها الثنائية) |
| `version.json` | رقم النسخة ورمزها، وارتفاع الويدجت الافتراضي |
| `build.py` | أداة البناء |
| `tools/Sign.java` | التوقيع والتحقق (apksig) |

## البناء

```bash
python3 android/build.py                                   # يبني ويفحص — بلا توقيع
HOLY_KEY_PASS='…' python3 android/build.py --key /مسار/خارج/المستودع/holy-release.p12
                                                           # يبني ويوقّع ويتحقق ⇒ android/dist/Holy-<النسخة>.apk
```

- تحتاج: Python 3 وJDK 17 أو أحدث (`javac` و`java`) فقط. لا Android Studio ولا Gradle ولا خوادم Google.
- الأدوات تنزل من Maven Central مرة واحدة إلى `android/.tools/` (لا تدخل المستودع)، وكل ملف يُفحص بـsha256.
- البناء ثابت: المصدر نفسه يعطي الملف نفسه كل مرة.
- التوقيع بالمخطط v2 (التطبيق يحتاج أندرويد 7.0 فأحدث، وكلها تقرأ v2).

## رفع النسخة

1. غيّر `code` و`name` في `version.json`.
2. التطبيق يكتب نسخته بنفسه في عدة أماكن داخل `smali/` (هكذا بُني أصلاً). `build.py` يرفض البناء ويسمّي كل مكان لا يطابق `version.json`: ‏`BuildInfo` · ‏`Net` (‏`HolyApp/…`) · ‏`MainActivity` · ‏`MainActivity$Bridge` · ‏`Updater` · ‏`Updater$1$1`.
3. ابنِ ووقّع، ثم ضع الملف في اللوحة: `APP_APK_CODE` و`APP_APK_NAME` و`APP_APK_B64` (التحديث الذاتي يعمل فقط بين نسختين بالمفتاح نفسه).

## 🔐 مفتاح التوقيع

- مفتاح التوقيع **لا يدخل هذا المستودع أبداً** (المستودع عام). ‏`.gitignore` يمنع `*.p12` و`*.jks` و`*.keystore` و`PASSWORD*`.
- احفظ المفتاح وكلمة سرّه عند المالك، ويمكن حفظهما كسرّين في GitHub (`HOLY_KEY_B64` و`HOLY_KEY_PASS`) لبناء نسخ لاحقة.
